# Saved visit discovery and read-only application path

This transfer slice connects the existing Clinical Notes route in independent staging to current-authority saved Visit discovery and the existing SavedVisitDocumentation renderer. Staff select a patient, list its saved visits and open its exact stored note/vitals. The production route and editor retain their existing behavior. No write, generation, transcription, rules, signature, full chart or provider path is enabled by this read-only screen.

The visits_schedule RPC takes an exact selected agency/patient, null or completed status, 1–50 rows and an exact 15-field cursor. Every page rechecks native session, identity, membership, patient and assignment under existing revocation locks. Cursor fields must match current authority and an existing same-patient anchor. UUID order is enumeration; the unchanged collector fetches all pages before clinical date sorting and refuses more than 10,000 visits. Multiple calls are not a consistent export snapshot.

Only six stored S4 fields are returned: id, patient_id, visit_date, visit_type, status and updated_date. Every returned artifact bundle is verified. This finite immutable S4 subset contains completed skilled-nursing visits only, so both supported status choices enumerate that same subset. It does not infer appointment times, signatures or missing notes. A successful empty list is authorized, not a substitute for denial or corruption.

Every returned page, including an empty one, commits an immutable private disclosure record before return. The audit includes opaque scope/version, returned UUIDs and page bounds, not notes, credentials or patient names. Audit failure withholds the response. The new table forces RLS, has no direct application grants/policies and no patient foreign key. The archive importer remains unchanged and uninstalled on hosted staging.

The actual-app test uses four real native accounts and one explicitly fictional S4 record created through the real API. It proves administrator cross-author discovery, assigned-clinician discovery, exact saved note/zero/weight rendering, denied unassigned/foreign direct links and no edit controls. Browser network allowances add only the three exact read RPCs. Local native tests cover paging, scope/anchor substitution, artifact/audit failure and both revocation orderings. The encrypted restore fixture preserves three committed list audits and tests restored list results transactionally. These are synthetic tests, not customer migration or complete clinical-workflow acceptance.

Patient-name retrieval for a saved record calls the unchanged authorized-patient wrapper, checks its membership against the fresh Visit scope and uses an identity-scoped, zero-retention query. This avoids mounting a second currentUser refresh owner underneath a parent that must hide content during reauthorization. Any patient/Visit error or recheck hides the saved content. The patient selector and read components stay mounted independently, so shared identity refresh does not create an unmount/refetch loop.
