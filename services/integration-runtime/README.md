# PennSync external integration runtime

This separate Railway service implements direct Anthropic AI/document extraction, SendGrid email, and Supabase private file operations. It is not a Base44 custom integration and does not replace or redeploy PennTrain. Provider keys are private Railway reference variables pointing at the existing authorized accounts. New encryption and identity-hashing keys were generated by Railway and never copied into source.

## Not a completed cutover

`INTEGRATIONS_RELEASE=disabled` and the allowed operation list is empty. PennSync's live frontend remains unchanged and still uses its current integrations. This branch's source, a healthy service, and provider metadata checks are separate from employee acceptance and production traffic switching.

**The runtime still invokes Base44 `getMyTenantContext` to verify current agency authority.** That remains a Base44 backend execution dependency. There is no claim of zero Base44 integration credits, measured savings, or complete migration. A supported external authority/data path is required to remove this last authorization callback without weakening permissions. Base44 documents that SDK service-role permissions cannot be used by an external backend; do not copy platform-injected service tokens or reopen private entities as a shortcut.

## Supported adapters and compatibility boundaries

- `InvokeLLM`: text and constrained structured output through Anthropic. Explicit unsupported model mappings and internet-search requests are rejected, not silently substituted.
- `ExtractDataFromUploadedFile`: only owner-bound private file handles created by this service; PDF/image/text supported within validated limits. Legacy public URLs are not fetched automatically.
- `SendEmail`: fixed server-side sender, bounded recipient count and privileged current membership. Text/plain body; provider acceptance is not delivery. Existing HTML template behavior still needs explicit migration.
- `UploadFile` / `UploadPrivateFile`: both store private bytes and return durable `cmfile:<uuid>` handles. They do not return permanent public `file_url` links. Existing upload consumers must migrate before switching them.
- `CreateFileSignedUrl`: exact owner-bound file, short-lived signed link. Treat it as a bearer capability and do not log it.

Image generation, external web search, telephony/fax, Stripe, provider-signing flows, external workers and a migration of all hosted backend functions are **not** delivered by these six adapters. Existing quarantined clinical/outbound/learning flags stay unchanged. Public file sharing and general recipient emailing are not substitutes for private workflow authorization.

## Security and retry behavior

Current authority is verified before reservation, before paid execution or replay disclosure, and after execution. The server rejects client-supplied tenant substitutions and never accepts provider/service-role credentials from client headers. Browser origins are exact; errors are no-store and contain only safe codes.

Dedicated SQL RPCs reserve idempotency keys with a per-actor lock and daily quota. The job ledger stores HMAC payload/subject identifiers, not plaintext prompts or recipients. Completed responses are AES-256-GCM encrypted with an exact job/owner binding. Uncertain or pending provider outcomes are not automatically rerun or silently routed back through Base44. Completed results cannot be overwritten by a later uncertainty response.

The caller must use a new request identifier for genuinely new work and preserve it for retries. An unabortable SDK timeout does not establish that the first paid operation stopped; the shared frontend retry fix prevents blindly starting another copy.

## Test and release procedure

1. `node --test services/integration-runtime/runtime.test.mjs`
2. Run existing full app CI, lint, high-signal typecheck and build for the complete proposed commit.
3. Require provider configuration, intended HTML/file/model compatibility, signed-in two-agency acceptance, encrypted-result retention/rotation, and actual provider-output checks before activating operations.
4. Wire the external transport beneath the existing browser authority boundary, not around it; no fallback that repeats uncertain paid work.
5. Verify the new request path and the workspace credit ledger before claiming any operation is independent of Base44 credits.

Seven previously paused backend workflows were confirmed inactive at the Base44 dashboard in the prior migration step. Their definitions, queues and history were retained. No external replacement job is enabled by this service, and their inactivity must be rechecked after future Base44 publications.
