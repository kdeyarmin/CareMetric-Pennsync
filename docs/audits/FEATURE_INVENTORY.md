- **Base44 entity contracts inventoried:** 236 JSONC entity definitions under `base44/entities`.

- **Status vocabulary:** Complete and working; Working but needs improvement; Partially implemented; Present but disconnected; Duplicated or conflicting; Broken or likely broken; Placeholder only; Missing but expected.

## Unrouted, duplicate, legacy, or disconnected page files

The route table explicitly states that not every page under `src/pages` is routed and that navigation is derived from `src/lib/nav.manifest.js`. Pages mentioned as retired/consolidated include `ClinicalChart`, `MyLearning`, `ClinicalInsightsDashboard`, `NurseEducationVideos`, `AnalyticsDashboard` and many legacy redirects in `src/routes.jsx`. These should be either removed after confirming content parity or documented as intentionally retained reference implementations.


## Phase 1 status update (2026-07-22)

- **F05 Referral intake and triage:** Improved. Referral triage now blocks active Patient creation when minimum identity is missing and queues an awaiting-info Referral/Task instead. Hosted end-to-end ReferralIntake validation remains required.
- **F06 Provider follow-up portal:** Improved. Provider follow-up tokens now persist expired/delivered statuses in backend functions; live token abuse/rate-limit verification remains required.
- **F12 Incident/event reporting and review:** Partially improved. Incident schema and lifecycle helper now support corrective-action/review/closure metadata; full UI migration remains pending.
- **F22 Personnel, credentials, user management:** Partially improved. User offboarding schema/helper now supports auditable deactivation; hosted auth/session revocation remains required.
- **F29 Admin operations/system jobs / navigation governance:** Improved. Route-manifest contract test now prevents accidental unrouted-page drift.

## Phase 2 status update (2026-07-22)

- **F02 Dashboard / today's priorities:** Partially improved. Role work-queue foundations from Phase 1 are now complemented by admin onboarding checklist logic; UI integration remains pending.
- **F03/F04 Patient list, details, and chart:** Partially improved. A patient timeline normalizer now creates sorted source-linked events from visits, documents, incidents, tasks, messages, and referrals; PatientDetails integration remains pending.
- **F09 Smart Note and mobile workflows:** Partially improved; real device validation remains required. (F10 offline mode has since been removed — see its row above.)
- **F24 Reports and analytics:** Improved repo-side. Canonical metric dictionary metadata now exists; stakeholder-approved UI adoption remains required.
- **F31 Public/static/token pages:** Partially improved. Public no-token route accessibility smoke metadata now exists; axe/browser execution remains required.

## Phase 3 status update (2026-07-22)

- **F09/F19 AI-assisted SmartNote and training workflows:** Partially improved. Shared AI provenance registry helpers now normalize, validate, filter, and export provenance-safe rows; persisted dashboard and retention policy remain pending.
- **F13/F24 ADR, documentation impact, and analytics:** Improved repo-side. Denial feedback normalization now maps payer feedback to documentation, OASIS, PDGM, referral, and ADR workflows; live payer integration remains pending.
- **F03/F05 Patient and referral interoperability:** Partially improved. FHIR-lite Patient and ServiceRequest import/export helpers now define a narrow EHR boundary; real EHR/FHIR sandbox validation remains pending.
